**Срез:** 2026-11-26 · **main:** `0d9b17ac6b42ceb11ac7c17430f6b6eb9dcae2b3` · **Платформа:** Paper 26.2 + Java 25  
**Версия разработки:** `1.16.0-SNAPSHOT` · **Последний официальный релиз:** `v1.15.8`

Документ связывает существующие спецификации, PR и тестовые контракты. Открытый PR не считается частью main до фактического merge.

## Правила движения

1. Сначала архитектурная надёжность и контракты, затем расширение игрового функционала.
2. Production-код определяет фактическое поведение; документация описывает решения, цели и ограничения.
3. Этап закрывается доказательствами: тесты, статический анализ, подходящий runtime QA и актуальные документы.
4. PR checks и post-merge checks — разные доказательства. Paper Watchtower — изолированный CI runtime, не production-сервер.
5. Не менять базы, ancestry и содержимое зависимых PR без отдельного аудита и разрешения.

### Правила выпуска 1.16.x

1. Каждый патч должен давать законченную, проверяемую функциональность и сохранять совместимость с уже выпущенными патчами серии.
2. Для каждого патча создаются отдельные PR, CI-доказательства, тесты новых функций и регрессии, документация и changelog.
3. Следующий патч не считается готовым только потому, что предыдущий смержен: он проходит собственные quality, integrity, storage и применимые runtime-проверки.
4. Внутренние итерации разработки (например, v160.x) не являются автоматически публичными версиями.
5. Фактическое распределение может быть уточнено при декомпозиции задач, но перенос функциональности между патчами фиксируется в ROADMAP и DECISIONS.
6. Ориентир 100–150 часов на путь 1–60 остаётся гипотезой баланса и проверяется на реальном игровом процессе.

### Границы релизов

- 1.16.0 создаёт основу персонажа и прогрессии; он не должен включать сразу все будущие подсистемы.
- 1.16.1–1.16.5 последовательно добавляют идентичность класса, специализацию, таланты, экипировку и глубокую боевую интеграцию.
- 1.16.6–1.16.7 добавляют удобство и игровое наполнение поверх устойчивого RPG Core.
- 1.16.8 закрывает стабилизацию всей серии. RASKOL Arena остаётся отдельным CI/validation потоком и не становится обязательной проверкой без отдельного решения.
