# Профиль персонажа 1.16.0 — схема и миграция

## Назначение

`characters.yml` — единое активное YAML-хранилище данных персонажа:

- уровень и опыт;
- основная специализация;
- ранги узлов всех деревьев специализации;
- ledger уже обработанных квестовых наград.

Класс по-прежнему определяется через LuckPerms и не дублируется в профиле. `Spec2Storage` сохранён как совместимый фасад для `Spec2Service`, но больше не владеет отдельным файлом.

## Файл и структура

Файл: `plugins/RaskolClasses/characters.yml`.

```yaml
schema-version: 3
profiles:
  <player-uuid>:
    schema-version: 1
    level: 1
    experience: 0
    created-at: 1795363200000
    updated-at: 1795363200000
    specialization:
      main: arms
      ranks:
        arms:
          arms_training: 2
processed-quest-rewards:
  <player-uuid>:
    - "quest:<quest-id>:<completion-uuid>"
```

- Верхний `schema-version: 3` задаёт версию общего файла. Схема самого профиля остаётся `1`.
- `level` находится в диапазоне 1–60.
- `experience` — накопленный опыт внутри текущего уровня; значение не может быть отрицательным. На 60-м уровне оно равно нулю.
- `specialization.main` содержит ID основной специализации либо отсутствует, если выбор ещё не сделан.
- `specialization.ranks` содержит ранги узлов в разрезе ID дерева и ID узла. В файл попадают только положительные ранги.
- `processed-quest-rewards` хранит квитанции идемпотентной выдачи XP.
- Временные метки хранятся в миллисекундах Unix.

## Миграция Spec 2.0 в единый профиль

До этой миграции специализация хранилась отдельно:

- `spec2-storage.yml` — актуальный формат;
- `spec2.yml` — legacy-формат;
- у обоих источников могли существовать файлы восстановления `.tmp` и `.bak`.

`Spec2StorageMigration` переносит их в `characters.yml` при старте:

1. Для каждого старого источника проверяется основной файл, затем его `.tmp` и `.bak`.
2. Если доступны оба источника, текущий `spec2-storage.yml` имеет приоритет. Уникальные записи из `spec2.yml` объединяются; конфликтующие значения остаются от текущего источника и логируются.
3. Данные из существующего `characters.yml` имеют приоритет над обоими старыми источниками. Старые ранги добавляются только для отсутствующих узлов.
4. Профили, прогресс и ledger квестовых наград сохраняются; верхняя schema version обновляется до 3.
5. После подтверждённой записи единого файла обновляется `characters.yml.bak` полным снимком, содержащим и специализацию.
6. Только после подтверждения записи и обновления backup исходные файлы и их временные копии архивируются с суффиксом `.migrated` (при совпадении имени добавляется числовой суффикс).

Если источник повреждён, но есть другой читаемый источник с данными, миграция использует пригодные данные и отдельно сообщает о повреждённой копии. Если нет пригодного источника, позволяющего безопасно восстановить данные, запуск останавливается: оригиналы не архивируются и не перезаписываются. Ошибка записи единого файла или обновления backup также останавливает миграцию до архивации источников.

## Безопасность данных и персистентность

- Все профили, ранги специализации и квестовые квитанции сериализуются одним `CharacterProfileStorage` в общий снимок.
- `Spec2Storage` делегирует чтение и изменение `CharacterProfileStorage`; отдельной записи `spec2-storage.yml` больше нет.
- YAML сериализуется на вызывающем потоке; `AsyncStorageWriter` получает готовую строку.
- `SafeStorage` обеспечивает атомарную запись через `.tmp`, резервную копию `.bak` и замену основного файла.
- Автосохранение, выход игрока и выключение плагина сохраняют единый профиль.
- Во время миграции используется `saveAndAwait`: архивирование старых источников запрещено до подтверждения успешной записи.
- Неизвестная будущая версия схемы и некорректная запись отклоняются явно, а не приводят к молчаливому сбросу профиля.

## Использование профиля в прогрессии

`CharacterExperienceService` начисляет XP через `CharacterProgressionEngine` и записывает уровень/остаток опыта в профиль. `CharacterLevelService` читает только этот профиль. AuraSkills, ванильный уровень Minecraft и среднее нескольких навыков не участвуют в расчётах. Требования способностей, атрибуты, специализации и ограничения экипировки используют единый уровень персонажа.

Старые игроки без собственного профиля начинают с уровня 1 и 0 XP — AuraSkills-уровень намеренно не переносится. Кривая и PvE-награды описаны в `V160_EXPERIENCE_PROGRESSION.md`.

## Проверки

`CharacterProfileStorageTest` и тесты Spec 2.0 покрывают:

- создание профиля первого уровня и сохранение прогресса;
- round-trip основной специализации и рангов в одном файле;
- обновление storage schema до 3 без изменения schema самого профиля;
- миграцию legacy-источника и объединение current + legacy;
- приоритет текущего источника и уже существующих данных `characters.yml`;
- сохранение прогресса и ledger квестовых наград;
- восстановление из backup и обновление unified backup до архивации;
- повреждённые источники, отказ записи и сохранность исходных файлов при ошибке;
- mutable snapshots рангов, необходимые текущему `Spec2Service`.
