# Профиль персонажа 1.16.0 — схема и миграция

## Назначение

Собственный профиль становится долговременным источником данных прогрессии персонажа. В текущем пакете он хранит уровень, опыт внутри уровня и ledger обработанных квестовых наград. Класс по-прежнему определяется через существующую интеграцию LuckPerms/Core, а данные специализации остаются в отдельном Spec2-хранилище. Целевая миграция к согласованной модели `yaml-single` ещё не завершена.

## Файл и структура

Файл прогрессии: `plugins/RaskolClasses/characters.yml`. Это единый атомарный файл для профилей уровня/XP и квестовых квитанций, но пока не единое хранилище всех игровых данных персонажа: Spec 2.0 продолжает использовать `spec2-storage.yml`.

```yaml
schema-version: 2
profiles:
  <player-uuid>:
    schema-version: 1
    level: 1
    experience: 0
    created-at: 1795363200000
    updated-at: 1795363200000
processed-quest-rewards:
  <player-uuid>:
    - "quest:<quest-id>:<completion-uuid>"
```

- `schema-version: 2` на верхнем уровне задаёт текущую версию всего файла; схема профиля внутри `profiles` остаётся `1`.
- Версия профиля позволяет валидировать и эволюционировать запись отдельно.
- `processed-quest-rewards` на верхнем уровне хранит квитанции идемпотентной выдачи XP за квесты; миграция storage schema 1 → 2 добавляет этот раздел, не сбрасывая профили.
- `level` находится в диапазоне 1–60.
- `experience` — накопленный опыт внутри текущего уровня; значение не может быть отрицательным.
- На 60-м уровне `experience` равен нулю: дальнейший избыток XP обрабатывается доменной политикой прогрессии.
- Временные метки хранятся в миллисекундах Unix.

## Миграция существующих игроков

До 1.16.0 отдельного собственного хранилища уровней персонажа не было: старый `CharacterLevelService` вычислял уровень из AuraSkills и fallback-конфигурации. AuraSkills полностью удалён из интеграций плагина. Поэтому мигрировать старый уровень из локального файла невозможно и не следует выдумывать источник.

Для существующего игрока без записи в `characters.yml` профиль создаётся при первом входе:
- уровень 1;
- опыт 0;
- `created-at` и `updated-at` фиксируются при создании.

Операция идемпотентна: повторный вход не перезаписывает уже существующий профиль. Офлайн-игроки создаются по мере следующего входа; сервер не выполняет массовое сканирование всех исторических UUID при запуске.

## Безопасность данных

- Запись использует общий последовательный `AsyncStorageWriter`.
- YAML сериализуется на основном потоке; фоновый поток получает только неизменяемую строку.
- `SafeStorage` обеспечивает атомарную запись и цепочку восстановления `main → .tmp → .bak`.
- Автосохранение выполняется вместе с остальными хранилищами.
- При выключении финальный снимок ставится в очередь до закрытия общего writer.
- Неизвестная будущая версия схемы и некорректная существующая запись приводят к явной ошибке загрузки, а не к автоматическому сбросу профиля.
- Legacy-схема без версии поддерживается ограниченной миграцией: отсутствующие поля получают безопасные значения, после чего файл помечается dirty и записывается в актуальном формате.

## Использование профиля в прогрессии

`CharacterExperienceService` начисляет XP через `CharacterProgressionEngine` и записывает обновлённый уровень/остаток опыта в профиль. `CharacterLevelService` больше не вычисляет среднее навыков и не использует fallback: он читает только профиль. Требования способностей, атрибуты, специализации и ограничения экипировки используют этот же уровень. PvE-награды описаны в `V160_EXPERIENCE_PROGRESSION.md`.

Старые игроки без собственного профиля начинают с уровня 1 и 0 XP — AuraSkills-уровень намеренно не переносится.

## Статус целевой миграции `yaml-single`

Текущая схема не должна трактоваться как завершённая миграция всех данных персонажа. До официального релиза 1.16.0 требуется спроектировать и протестировать объединение профиля, основной специализации и рангов деревьев без потери существующих данных. До отдельного миграционного пакета `spec2-storage.yml` остаётся самостоятельным источником сохранённых рангов.

## Проверки

`CharacterProfileStorageTest` покрывает:
- создание профиля первого уровня ровно один раз;
- сохранение и повторную загрузку без сброса прогресса;
- миграцию legacy-схемы с сохранением уже существующего уровня;
- отказ на неизвестной будущей версии без перезаписи исходного файла;
- отказ на некорректном UUID и уровне вне диапазона вместо молчаливого создания/сброса профиля.
