# Журнал архитектурных решений

**Актуальность:** 2026-11-26

Здесь фиксируются решения, подтверждённые пользователем или существующей документацией. Предложения не становятся обязательными решениями автоматически.

## ADR-001 — Целевая платформа
**Статус: принято.** Paper 26.2 + Java 25. Maven compiler release и CI соответствуют целевой платформе.

## ADR-002 — Собственная прогрессия персонажа
**Статус: принято, частично реализовано.** Уровень 1–60 — собственная шкала. AuraSkills не является источником уровня и удалён из интеграций. PvE XP выдаётся по разрешённым правилам; убийства игроков RPG XP не дают.

## ADR-003 — Class Lock
**Статус: принято и реализовано в main; live-проверка открыта.** Класс определяется через единственную подтверждённую primary-группу LuckPerms `class_<NAME>`. При неоднозначном состоянии класс не выбирается произвольно.

## ADR-004 — Spec 2.0
**Статус: принято; интеграция частичная.** Специализация `v160`, выбор с 15 уровня, три специализации на класс, бюджет 46 очков.

## ADR-005 — Storage 1.16.x (target 1.16.0)
**Статус: целевая модель принята, миграция не завершена.** Цель — `yaml-single`; миграция должна сохранять профили и specialization state, иметь backup и проверяемый rollback.

## ADR-006 — Soul Tome
**Статус: принято, релизная интеграция открыта.** Политика — `replace`: проверяемая замена class group с обработкой неуспеха и откатом.

## ADR-007 — RIPS integrity
**Статус: принято и реализовано.** Проверки при старте и периодически в runtime; интервал — 1800 секунд. Подпись официального артефакта и trusted public key не обходятся и не подменяются.

## ADR-008 — Combat event context
**Статус: интегрировано PR #80.** Вложенный контекст источника способности восстанавливается стеково (LIFO), привязан к потоку-владельцу и безопасно отвергает повторное/чужое закрытие scope. Merge commit: `0d9b17ac6b42ceb11ac7c17430f6b6eb9dcae2b3`.

## ADR-009 — Burst reservation settlement
**Статус: PR #81, не интегрировано.** Path B reservation сверяется с фактически применённым уроном и завершается ровно один раз, включая cancellation/partial/exception paths.

## ADR-010 — RASKOL Arena ownership
**Статус: архитектура согласована; Arena-01 не интегрирован.** Arena не дублирует Forge Maven/quality gates и Watchtower Paper runtime. Она отвечает за combat diff audit, report/schema validation, headless deterministic scenarios и statistical comparison после утверждения baseline. На Arena-01 не менять пять действующих required checks и не включать Arena как required check до отдельного решения. 20 talent nodes остаются disabled; таланты исключены из Arena-01.

## ADR-011 — PR dependency safety
**Статус: принято.** Не выполнять merge, rebase, смену base или force-update зависимых веток без явного разрешения. Открытые PR не считать интегрированными. Перед интеграцией проверять diff, ancestry, required checks и runtime evidence.


## ADR-012 — План выпусков 1.16.x
**Статус: принято.** RPG-перестройка выпускается последовательно, а не целиком в 1.16.0. Принятая разбивка:
- 1.16.0 — RPG Foundation;
- 1.16.1 — Class System;
- 1.16.2 — Specialization;
- 1.16.3 — Talents;
- 1.16.4 — Soul Tome & Equipment;
- 1.16.5 — Combat & Attributes;
- 1.16.6 — Character Interface;
- 1.16.7 — Progression Content;
- 1.16.8 — RPG Core Stabilization.

Состав и критерии этапов подробно описаны в ROADMAP.md. Это план релизной последовательности, а не статус реализации. Каждый патч требует отдельного PR, собственных тестов и release evidence. Изменение границ патчей документируется; внутренние v160.x не считаются публичными версиями автоматически.


## Формат новых записей

Каждая запись включает ID, статус (Proposed / Accepted / Implemented / Superseded), дату, контекст, решение, последствия/ограничения и ссылки на PR/тесты/документы. Отменённое решение не удалять: пометить Superseded и сослаться на замену.
