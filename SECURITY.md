# Политика безопасности RaskolClasses

## Поддерживаемые версии

Список версий, для которых выпускаются обновления безопасности (исправление критических уязвимостей).

| Версия | Поддержка          |
| ------ | ------------------ |
| 1.15.x | :white_check_mark: |
| 1.14.x | :white_check_mark: |
| 1.13.x | :x:                |
| < 1.13 | :x:                |

**Правило поддержки:** исправления безопасности выпускаются только для последних двух минорных веток (текущая стабильная и предыдущая). Более старые версии получают критические патчи только по запросу куратора проекта.

## Как сообщить об уязвимости

**НЕ создавайте публичный GitHub Issue для уязвимостей** — это даёт злоумышленникам время на эксплуатацию до выпуска исправления.

### Каналы связи (в порядке приоритета)

1. **GitHub Security Advisories** (рекомендуется):
   - Откройте вкладку **Security** → **Advisories** → **Report a vulnerability**
   - Заполните форму: затронутые версии, шаги воспроизведения, оценка критичности
   - GitHub автоматически уведомит мейнтейнеров и создаст приватный тред

2. **Прямой контакт с мейнтейнером:**
   - Discord: `hayferdahmer` (если есть общий сервер проекта)
   - Email: по запросу через Discord (не публикуется открыто для защиты от спама)

### Что указать в отчёте

Для быстрой диагностики включите в сообщение:

- **Версия плагина** (из `/rc version` или `plugin.yml`)
- **Версия Paper/Spigot** (из `/version`)
- **Версия Java** (из `java -version`)
- **Шаги воспроизведения** (минимальный набор действий)
- **Ожидаемое поведение** vs **фактическое**
- **Оценка критичности** (CVSS-скор или описание: RCE/привилегии/утечка данных/DoS)
- **PoC-код или скриншоты** (если есть)

### SLA обработки

| Этап | Срок |
| ---- | ---- |
| Подтверждение получения | ≤ 72 часов |
| Первичная оценка критичности | ≤ 7 дней |
| Выпуск патча (критические уязвимости) | ≤ 30 дней |
| Выпуск патча (средние/низкие) | ≤ 90 дней или ближайший минорный релиз |

### Что ожидать после отправки

**Если уязвимость принята:**

1. Мейнтейнер подтвердит получение и назначит внутренний трекер
2. В приватном треде согласуем план исправления и сроки
3. После выпуска патча — публичное раскрытие с упоминанием репортёра (если согласен)
4. CVE-идентификатор запрашивается мейнтейнером (опционально, по запросу репортёра)

**Если уязвимость отклонена:**

- Объяснение причины (не уязвимость / working as intended / вне скоупа проекта)
- Возможность эскалации через GitHub Security (если репортёр не согласен с оценкой)

## Публичная поверхность плагина

Команды, доступные всем игрокам (не требуют привилегий):

| Команда | Назначение |
| ------- | ---------- |
| `/rc version` | Показать версию плагина, билд-хэш, статус RIPS-верификации (публичная информация) |
| `/rc menu` | Открыть Книгу класса (GUI) |
| `/rc health` | Показать свои HP/ресурс (actionbar-формат) |
| `/rc plus status` | Статус подписки raskolspec+ (активна/неактивна, осталось дней) |
| `/rc plus buy` | Купить подписку за империалы (PlayerPoints) |
| `/rc plus gift <player> <days>` | Подарить подписку другому игроку |
| `/rc plus apply <template>` | Применить курируемый билд (требует активную подписку) |
| `/rc item stats` | Показать статы своего снаряжения |
| `/rc item salvage` | Разобрать предмет в руке на фрагменты |
| `/rc item craft` | Открыть GUI крафта из фрагментов |

## Привилегированные команды

Команды, требующие `raskolclasses.admin` или `op`:

| Команда | Назначение | Право |
| ------- | ---------- | ----- |
| `/rc reload` | Перезагрузка конфигов (config.yml, kits/*.yml, crafting.yml) | `raskolclasses.admin` |
| `/rc debug [player]` | Диагностика: атрибуты, ресурсы, CC-стек, burst-лог | `raskolclasses.debug` |

| `/rc plus grant <player> <days>` | Выдать подписку raskolspec+ бесплатно (админ) | `raskolclasses.admin.plus` |

| `/rc item reload` | Перезагрузка реестра предметов (items.yml) | `raskolclasses.item.reload` |

| `/rc item browse` | Админ-браузер всех предметов реестра | `raskolclasses.item.browser` |

## Скоуп (что входит в программу)

### Входит

- Уязвимости в коде плагина RaskolClasses (Java-код, YAML-конфиги, resource-файлы)
- Уязвимости в API для интеграций (RaskolMobs, внешние плагины)
- Уязвимости процесса сборки (pom.xml, GitHub Actions workflows)
- Проблемы в зависимостях, эксплуатируемые через код плагина
- Обход permission-гейтов (игрок без `raskolclasses.admin` вызывает admin-команду)
- RIPS-подделка артефактов (обход `ArtifactBoundIntegrityVerifier`)

### Не входит (out of scope)

- Уязвимости в Paper/Spigot/Bukkit (сообщайте в их проекты)
- Уязвимости в сторонних плагинах на сервере
- Социальная инженерия (фишинг админов сервера)
- Физический доступ к серверу
- Уязвимости, требующие доступа к исходному коду сервера (который вы и так имеете как админ)
- Баги геймплея без security-последствий (эксплойты механик — отдельный канал)

## Благодарности

Репортёры, чьи уязвимости были подтверждены и исправлены, упоминаются в `CHANGELOG.md` и в GitHub Security Advisories (с согласия репортёра). Критические находки получают отдельную благодарность в release notes.

## Раскрытие информации

- **Координированное раскрытие:** патч выпускается ДО публичного описания уязвимости
- **Эмбарго:** 90 дней с момента подтверждения (или до выпуска патча — что раньше)
- **Исключения:** 0-day в активной эксплуатации — раскрытие немедленно с одновременным выпуском хотфикса
