## [1.6.13] — 2026-09-10 · «Самотестирование»

### Added
- **Команда `/rc selftest`** (permission `raskolclasses.debug`): headless-
  самотестирование плагина, PASS/FAIL-список с итоговой строкой. Семь групп
  проверок, ничего не мутирует:
  1. **Формула резистов:** согласованность симулятора (`simulateTaken`)
     с факторами (`physicalFactor`/`magicFactor`) на живом состоянии
     онлайн-игрока; `[SKIP]` если онлайн-игроков нет или игрок в мире из
     `resist.disabled-worlds`;
  2. **Клампы и NaN-гарды:** cap=0 → 0, cap=100 → ≤100, NaN-cap → конечный
     фактор (headless, без мутаций);
  3. **Целостность реестра:** у каждой способности есть кастер (self или
     targeted), targeted-пары полны, нет сиротских кастеров вне DEFAULTS
     (`AbilityRegistry.integrityProblems()`);
  4. **PDC-раундтрип токенов:** ability/spec/install-свитки создаются и
     читаются обратно, пустой предмет не читается как свиток (временные
     предметы в памяти, без мира и без выдачи игрокам);
  5. **Полнота спек-реестра:** у каждого `Spec` есть `SpecDef`;
  6. **Конфиг-валидация:** диапазоны/типы/конечность резистов и урона
     (прогон `ConfigValidator`);
  7. **Fx-каталог:** все имена звуков/партиклов резолвятся.
- **`AbilityRegistry.integrityProblems()`:** список проблем целостности
  реестра (способности без кастеров, targeted без self-кастера, сироты) —
  источник данных для проверки 3.
- Таб-комплит `/rc`: добавлен `selftest` в корневой список, гейт
  `raskolclasses.debug` (как у `debug`/`health`).

### Changed
- Версия в pom/plugin.yml: 1.6.13; артефакт `raskol-classes-1.6.13.jar`.

## [1.6.12] — 2026-09-10 · «Наблюдаемость»

### Added
- **Команда `/rc health`** (permission `raskolclasses.debug`) — сводка
  наблюдаемости для оператора, все строки однострочные:
  - MSPT-снапшот (`Server#getAverageTickTime`, 2 знака) + TPS (первое значение

  - модификаторы резиста: игроков / записей / размер кэша факторов;
  - кулдауны: игроков / записей;

  - proc-кулдауны Fx: игроков;
  - звуковой бюджет: сброшено звуков с прошлого `/rc health`
    (окно сбрасывается опросом — семантика «с прошлого вызова»);
  - последний purge: N с назад; аптайм плагина.
- **Метрики FxService:** счётчик `droppedSoundsWindow` (инкремент в ветке
  сброса бюджета в `playSound`), `pollDroppedSounds()` (возврат + сброс окна),
  `procVisualCdSize()`.
- **Метрики CooldownManager:** `trackedPlayers()`, `totalEntries()`.
- **Метрики ResistService:** `trackedPlayers()`, `totalModifiers()`,
  `factorCacheSize()`.
- **Отметки RaskolClasses:** `lastPurgeMillis` (обновляется в purge-таске),
  `enabledAtMillis` (на onEnable) + геттеры для `/rc health`.

- **Политика WARNING задокументирована:** однострочные сообщения без

  стек остаётся только в SafeStorage SEVERE (коррупт хранилища).
- Версия в pom/plugin.yml: 1.6.12; артефакт `raskol-classes-1.6.12.jar`.

## [1.6.11] — 2026-09-10 · «Анти-эксплойт и sanity»

### Added
- **LOS-проверка AoE сквозь стены (`combat.aoe-los`, дефолт true):**
  `Targeting.hasLineOfSight` трассирует луч из глаз кастера в глаза цели
  через `rayTraceBlocks` (FluidCollisionMode.NEVER). Применяется к
  боевым AoE: frost_nova, arcane_burst, fan_of_knives, спек FROST.
  Стекло/камень/двери блокируют урон; вода/воздух/трава — проходят.
  **Хиляющие AoE (circle_of_prayer, smite-хил) LOS не получают намеренно:**
  саппорт через стену — нормальный геймплей, задокументировано.
  Гейт `combat.aoe-los: false` возвращает старое поведение.
- **NaN/Infinity-гарды в боевой математике:**
  - `CombatService.dealDamage`/`simulateTaken`: `sanitize(DamageProfile)`
    обнуляет некорректные компоненты (NaN, Infinity, отрицательные) до
    применения урона — битый конфиг урона не падает в NaN-урон.
  - `ResistService.clamp` и `physicalFactor`/`magicFactor`: защита от
    NaN-значений, кламп фактора в [0..1], фолбэк на 1.0 (урон не режется)
    при любой некорректности.
  - `ResourceService`: санитаризация `sanitize()` на всех публичных входах
    (add/refund/consume/addHealBonus, тики регена всех классов) —
    битое значение из конфига или хука не может сломать ресурс или унести
    его за границы.
- **ScrollSanitizer — чистка устаревших свитков на join:**
  слушатель `hotbar/ScrollSanitizer` при входе игрока удаляет из инвентаря
  свитки с мёртвыми/неизвестными id (после переименований абилок/спеков/
  инсталляций между сезонами). Игрок получает одно уведомление
  «Удалены устаревшие классовые свитки: N». Работает на join
  (достаточно редко и безопасно для производительности).

### Changed
- **`AbilityRegistry`:** добавлен `exists(String id)` — пробег по всем
  классам в поиске абилки; используется ScrollSanitizer.
- **`SpecToken`:** добавлен `isSpecScroll(ItemStack)` — проверка
  PDC-ключа `spec_ability` для санитизатора.
- **`InstallToken`:** добавлен `isInstallScroll(ItemStack)` — проверка
  PDC-ключа `install` для санитизатора.
- **`MageAbilities.frostNova` / `arcaneBurst`:** цели за стенами
  пропускаются через `Targeting.hasLineOfSight`.
- **`RogueAbilities.fanOfKnives`:** цели за стенами пропускаются.
- **`SpecActiveCaster` спек FROST:** цели за стенами пропускаются.
- Версия в pom/plugin.yml: 1.6.11; артефакт `raskol-classes-1.6.11.jar`.

## [1.6.10] — 2026-09-10 · «Надёжность хранения»

### Added
- **`storage.SafeStorage` — универсальный безопасный сейвер YAML:**
  - `saveAtomic`: пишем в `<file>.tmp` → предыдущую версию уносим в `<file>.bak` →
    атомарно переименовываем tmp в целевой файл. После обесточки/`kill -9` на
    диске не может остаться полубитого yml: есть либо целостный текущий, либо `.bak`.
    Фолбэк на `REPLACE_EXISTING` на ФС, не поддерживающих `ATOMIC_MOVE`.
  - `loadWithFallback`: при битом YAML — WARNING одной строкой и попытка чтения
    `.bak`; если и `.bak` бит/отсутствует — пустая конфигурация + SEVERE в лог
    (инцидент виден оператору, плагин поднимается, данные с нуля).
- **Автосейв хранилищ:** таск в `RaskolClasses` каждые `storage.autosave-minutes`
  (дефолт 5) пишет `cooldowns.yml` и `spec-choices.yml` через SafeStorage.
  При краше теряется не более N минут кулдаунов; спек-выборы не теряются
  вовсе (сейв на каждое изменение уже был, теперь он атомарный).

### Changed
- **`CooldownManager`:** конструктор использует `SafeStorage.loadWithFallback`
  (битый `cooldowns.yml` больше не роняет загрузку молча), `persist()` —
  `SafeStorage.saveAtomic`. Поведение ready-notify и персиста на join/quit
  без изменений.
- **`SpecStorage`:** `load()` на `SafeStorage.loadWithFallback` (битый
  `spec-choices.yml` → `.bak` → пустая конфигурация с SEVERE), `save()` —
  `SafeStorage.saveAtomic`. Сейв на каждое изменение (`set`/`remove`)
  сохранён — выбор и отречение спеки не теряются.
- Версия в pom/plugin.yml: 1.6.10; артефакт `raskol-classes-1.6.10.jar`.

## [1.6.9] — 2026-09-10 · «Баланс-рубильники»

### Added
- **`resist.disabled-worlds`:** список миров, где резисты не применяются вовсе
  (арены, спавн-хабы) — путь A, путь B и симулятор `/rc debug` ведут себя
  согласованно (урон проходит целиком).
- **`resist.pvp-cap`:** отдельный кап суммарного резиста для урона, пришедшего
  от игрока (прямой удар или снаряд с шутером-игроком; в пути B — source-игрок).
  Дефолт равен `resist.cap` → поведение по умолчанию не меняется; значение 0
  полностью выключает резисты в PvP (режим дуэльных арен).
- **`combat.true-damage-cap-per-hit`** (дефолт 1000): предохранитель компоненты
  чистого урона профиля за один вызов — защита от опечаток баланс-конфига и
  fuse для будущего контента 1.7.x; применяется в `dealDamage` и
  `simulateTaken` согласованно.

### Changed
- `ResistService`: breakdown и факторы принимают кап параметром; PvE-кэш
  факторов (на игрока на тик) сохранён, PvP-путь считает по вызову
  (корректность важнее микрооптимизации).
- Версия в pom/plugin.yml: 1.6.9; артефакт `raskol-classes-1.6.9.jar`.

## [1.6.8] — 2026-09-09 · «Края и совместимость»

### Added
- **Килл-кредит владельцу инсталляций:** при срабатывании капкана/руны
  онлайн-владелец передаётся как `source` в `CombatService.dealDamage`:
  дроп с моба, статистика убийств AuraSkills и смерть-лог видят убийство
  ловушкой как убийство владельцем. Оффлайн-владелец → `source = null`,
  урон проходит без кредита (безопасный фолбэк).
- **Spectator/creative-гард в обоих путях урона:** зрители пропускаются
  в пути A (`EntityDamageEvent`) до вычислений; зрители и креативщики
  пропускаются в пути B (`dealDamage`) — ванильная неуязвимость соблюдается
  без лишних вызовов и без рисков флага `SUPPRESS`.
- **Явное перечисление средовых причин в карте типов:** `CRAMMING` и
  `DRYOUT` теперь явно помечены `PHYSICAL` в `DamageType.defaultFor`,
  чтобы их типизация не менялась молча при будущих сменах дефолтов Bukkit.

### Changed
- **MELTING намеренно не трогаем:** константа `DamageCause.MELTING`
  deprecated в новых билдах Paper, событие фактически не возникает.
  CI-гейт по deprecation важнее мёртвой ветки.
- Версия в pom/plugin.yml: 1.6.8; артефакт `raskol-classes-1.6.8.jar`.

### Fixed
- **1.6.8.1:** восстановлен метод `CombatService.simulateTaken`, случайно
  потерянный при замене `CombatService` для 1.6.8 (ссылка из симулятора
  `/rc debug` ломала компиляцию всего модуля).

## [1.6.7] — 2026-09-09 · «Харденинг конфига»

### Added
- **ConfigValidator:** проверка конфига резистов/урона на старте и при
  `/rc reload`: диапазоны 0..100 и конечность (ловит `.nan`/`.inf`) для
  `resist.cap`, `resist.classes.*`, `resist.grants.*`, `resist.mana-soaked.*`,
  `resist.specs.*`; значения `damage-types.vanilla-map.*` из множества
  {physical, magic, true}; `damage-physical`/`damage-magic` способностей и
  инсталляций ≥ 0. Каждое нарушение = WARNING с путём ключа; рантайм-безопасность
  обеспечена клампом итога в ResistService и фолбэками в CombatService.typeOf,
  поэтому битое значение не роняет бой, а подменяется дефолтом/зажимом.
- **Стартовая сводка баз:** строка в лог «Базы резистов (маг/физ):
  WARRIOR 12/27; ROGUE 12/14; MAGE 26/12; PRIEST 30/16; HUNTER 12/16; кап 90».

### Changed
- ClassBook: ключ сообщения маг-гранта переименован в
  `book.resist.grant-magic` (плоский ключ; прежний `grant.magic` был
  недостижим через path-API Bukkit, т.к. ключ `grant` занят строкой физ-гранта).
- Версия в pom/plugin.yml: 1.6.7; артефакт `raskol-classes-1.6.7.jar`.

## [1.6.5] — 2026-09-09 · «PAPI-плейсхолдеры резистов»

### Added
- **Три новых PAPI-плейсхолдера** в экспансии `raskolclasses`:
  - `%raskolclasses_phys_resist%` — итоговый физрезист игрока, целое %
    (0, если класс не выбран);
  - `%raskolclasses_magic_resist%` — итоговый магрезист, целое %;
  - `%raskolclasses_resist_mods%` — список активных модификаторов через
    запятую (например, «steel_skin, guardian»), или «нет» если бафов нет.
- Существующие три плейсхолдера (`class`, `resource`, `resource_max`)
  не тронуты — прошитые в TAB/скорборд/холотемы шаблоны продолжают работать.
- **Рекомендация по применению:** по умолчанию резисты **не выводить**
  в основной TAB-список (информационный шум и раскрытие тактики противнику).
  Целевое применение: персональные скорборды игрока (по его выбору),
  дуэльные арены (отдельный табло-оверлей во время дуэли), holo-табличка
  герольда со статическими базами резистов классов, админ-GUI.

### Changed
- Версия в pom/plugin.yml: 1.6.5; артефакт `raskol-classes-1.6.5.jar`.

## [1.6.2] — 2026-09-08 · «Справедливость боя»

### Added
- **Фракционно-осознанные таргеты (B4):** хелпер `Targeting` в `combat/`
  определяет союзников через FactionHook (одна непустая фракция = союзники;
  сам себе — всегда союзник). Применяется в AoE-способностях
  (arcane_burst, frost_nova, fan_of_knives) и точечных (cheap_shot):
  союзники не получают урона от наших атак.
- **Фильтр союзников для хила/щитов:** lesser_heal/flash_heal/pw_shield через
  ЛКМ-свиток и circle_of_prayer/smite-хил работают только на себе и союзниках;
  попытка хильнуть врага = «Цель не союзник» без списания ресурса.
- **Гейт `combat.friendly-fire`:** дефолт `false` (союзники неуязвимы,
  хилы только своим); `true` возвращает старое поведение (AoE бьёт всех,
  хилы на кого угодно) — для хардкор-арен и дуэльных зон.
- **frost_nova получила врагов-игроков:** раньше била только мобов,
  теперь — всех, кто не союзник; союзники пропускаются.
- **Сообщения:** `messages.ally.no-hit` («Союзника бить нельзя») и
  `messages.ally.no-heal` («Цель не союзник») — локализация отказов.

### Changed
- Мобы по-прежнему бьются без ограничений (регресс не затронут).
- При отказе от каста (союзник в таргете) ресурс и кулдаун не списываются
  через штатный механизм отмены в AbilityRegistry.
- Версия в pom/plugin.yml: 1.6.2; артефакт `raskol-classes-1.6.2.jar`.

### Fixed
- PriestAbilities: восстановлена структура класса (была повреждена
  при копировании, компиляция ломала весь модуль).

## [1.6.0] — 2026-09-07 · «Система урона и сопротивлений»

### Added
- **Четыре вида урона:** физический (оружие, руки, падение, утопление),
  магический (способности, яды, огонь), гибридный (физ+маг компоненты в одном
  профиле), чистый (игнорирует резисты и броню целиком).
- **Система сопротивлений (РЕЗИСТ):** магрезист и физрезист; формула
  «получено = компонент × (1 − резист/100)»; базы по классам:
  Воин 12/27, Разбойник 12/14, Маг 26/12, Жрец 30/16, Охотник 12/16 (маг/физ);
  кап суммарного резиста `resist.cap` (дефолт 90).
- **CombatService:** путь A — ванильный урон режется резистом своего типа
  (карта причин → тип с конфиг-оверрайдами `damage-types.vanilla-map`);
  путь B — наш урон через `dealDamage(target, source, DamageProfile)`:
  физ-компонента проходит броню, маг+чистый — через DamageSource
  minecraft:magic (броню не трогает). Двойного применения резиста нет
  (ThreadLocal-маркер своих вызовов).
- **Модификаторы резиста (пакет 3):** Стальная кожа +15 физ (5 с),
  Уклонение +30 физ (4 с), спек-пассивка Стража +10 физ постоянно
  (переживает релог, снимается респецом), «Пропитанный маной»
  +15 физ/маг при мана ≥ 50 (ManaSoakedService, переключение раз в 1 с).
- **Числа урона в конфиге:** `damage-physical` / `damage-magic` у способностей
  и инсталляций (баланс без пересборки).
- `/rc` — строка «Резисты: физ X% · маг Y%»; `/rc debug` — разбивка
  «база + активные модификаторы + итог».

### Changed
- Урон способностей переведён на профили: маг firebolt = гибрид 30/70,
  frost_nova/arcane_burst = маг; жрец smite = маг; разбойник fan_of_knives/
  cheap_shot = физ; инсталляции bear_trap = физ, frost_rune = маг;
  спек-активки shadowweaver/frost = маг, liquidator = физ.
  Охотник (стрелы = ванильный PROJECTILE) и воин (возврат blood_fury через
  событие) типизируются путём A автоматически.
- «Пропитанный маной»: старый механизм (−15% входящего урона через событие)
  заменён честным резистом; `classes.MAGE.passives.mana_soaked.enabled: false`.
- Описания: Стальная кожа «+15% физрезиста на 5 с», Уклонение
  «+30% физрезиста на 4 с» (вместо «−80% урона» и «100% уклонение»).
- Версия в pom/plugin.yml: 1.6.0; артефакт `raskol-classes-1.6.0.jar`.
