# RaskolClasses

Paper 1.21.x · Java 21 · линия 1.9.x · **1.8.x закрыта с 1.8.1, 1.7.x и 1.6.x заморожены**

Пять классов с ресурсами и активными способностями, специализации как
пассивная идентичность, дерево талантов спеки в Книге класса, сводный уровень
персонажа, инсталляции, королевские вкусы (короны/титулы/ауры) и полная боевая
математика: четыре вида урона, сопротивления, модификаторы, burst-окно,
анти-ваншот и TTK-харнесс — всё тюнится без пересборки.

## Состав системы

- **Классы:** Воин, Охотник, Жрец, Маг, Разбойник. Ресурс 0–100 с правилами
  регена по классам (тиры маны мага, декей ярости воина вне боя, концентрация
  охотника только вне боя, свет жреца всегда, энергия разбойника).
- **Способности:** слоты 1–5 (лестница открытия 10/25/50/65/75), свитки в хотбар
  (ПКМ — каст в себя, ЛКМ по союзнику — точечный каст жреца), полоска
  перезарядки на свитке. Все числа = base + Power×coeff (WP/SP/HPow).
- **Специализации (с 1.7.5 — пассивная идентичность):** две на класс, выбор с 40
  уровня профильного скилла; резисты/проки/коэффициенты работают постоянно.
  Активки и свитки спеков удалены (ScrollSanitizer сжигает устаревшие свитки на
  join); платный респец с двойным подтверждением 30 с.
- **Уровень персонажа (1.8.0):** floor(среднее топ-N скиллов AuraSkills),
  кап `attributes.level-cap` (60). Атрибуты растут от сводного уровня; одиночное
  дерево до 99 не раздувает статы. Анлоки способностей остаются на профильном скилле.
- **Дерево талантов спеки (1.9.0):** 10 деревьев × 9 узлов (2 ветки A/B, 4 тира,
  капстоуны и ульт). Очки = clamp(charLevel − 39, 0, 21). Покупка и сброс —
  ТОЛЬКО в Книге класса (вкладка TALENTS): клик по узлу, кристалл сброса с
  двойным ПКМ. Эффекты узлов: attr / resist / kit_base / kit_mult / cd / regen /
  avoid / proc. Отдельных команд талантов нет (решение владельца).
- **Инсталляции:** ставящиеся мины/варды (слот 7), TTL, лимиты 2/200,
  килл-кредит владельцу, notify владельцу, гейты зон.
- **Короны:** Рассвет/Вальрадис — титулы классов и партикл-ауры (%raskolcrown_*%).
- **Бой:** типы урона physical/magic/hybrid/true; резисты по классам;
  модификаторы (эффекты, спек-пассивки, таланты, динамический mana-soaked);
  PvP-кап; миры без резистов; friendly-fire гейт (союзники не получают урон и в
  ванильном пути); LOS для AoE; burst-окно (3 с ≤ 18% maxHP); анти-ваншот
  (одиночный.hit ≤ 35% maxHP, исключения — среда и execute-финишеры); летальность
  среды × maxHP/20; Towny-гейт блинка «Шага Гермеса» (fail closed).
- **TTK-харнесс (1.7.6):** `/rc debug simulate [A] [B] [level]` — headless-дуэль
  на боевых формулах; `/rc debug simulate matrix [level]` — матрица 5×5;
  якорь `balance.target-ttk-seconds` (20 с), коридор ±30%.
- **Диагностика:** `/rc debug` (атрибуты, резисты, симулятор урона, таланты),
  `/rc health` (метрики живого сервера), `/rc selftest` (28 проверок).
- **Надёжность:** атомарные сейвы хранилищ с `.bak` и автофолбэком
  (cooldowns.yml, spec-choices.yml, talents.yml, resources.yml, health.yml),
  автосейв, валидатор конфига, NaN-гарды, санитизация устаревших свитков.

## Требования и совместимость

- Paper 1.21.4+ (целевой билд), Java 21.
- softdepend (каждый опционален, деградация graceful):
  LuckPerms (классы), AuraSkills (уровни скиллов и сводный уровень),
  PlaceholderAPI (плейсхолдеры), RaskolCore (паспорта классов),
  Towny (клеймы инсталляций и гейт блинка), AuthMe (гейт до логина),
  Vault/Economy (плата респеца и сброса талантов).

## Установка

1. `mvn -B clean package` → `target/raskol-classes-<version>.jar`.
2. jar в `plugins/`, рестарт сервера.
3. `config.yml` создаётся автоматически; правки применяются через `/rc reload`
   без рестарта (кроме `hp-display.mode`).
4. Хранилища: `cooldowns.yml`, `spec-choices.yml`, `talents.yml`,
   `resources.yml`, `health.yml` — атомарная запись, `.bak`-копии, автосейв
   каждые `storage.autosave-minutes`.

## Команды и права

| Команда | Право | Назначение |
|---|---|---|
| `/rc` | — | сводка игрока: класс, уровень персонажа, ресурс, резисты, корона, спека |
| `/rc 1–5` | — | каст способности слота |
| `/rc 6` | — | справка: спека = пассивная идентичность, таланты — в Книге |
| `/rc 7` | — | постановка инсталляции своего класса |
| `/rc menu` | — | Книга класса (4 вкладки: способности, спеки, класс, таланты) |
| `/rc reload` | `raskolclasses.admin` | перезагрузка конфигурации + reconcile талантов |
| `/rc debug [player]` | `raskolclasses.debug` | атрибуты, резисты, симулятор урона, таланты, КД |
| `/rc debug simulate [A] [B] [level]` | `raskolclasses.debug` | headless-дуэль TTK-харнесса |
| `/rc debug simulate matrix [level]` | `raskolclasses.debug` | матрица 5×5 TTK |
| `/rc health` | `raskolclasses.debug` | MSPT/TPS, purge, аптайм |
| `/rc selftest` | `raskolclasses.debug` | headless-самотестирование, 28 проверок |

Таланты управляются только через Книгу класса (вкладка TALENTS): просмотр своего
дерева, покупка кликом, сброс кристаллом. Чужое дерево недоступно.

## Регресс-матрица 1.9.x (30 пунктов)

Полный прогон перед любым хотфиксом и релизом. Порядок: диагностики (1–5),
бой (6–16), контент (17–30).

## Соглашение по версиям

- **1.9.x** — активная линия: эволюция талантов и харнесса, баланс-патчи.
- **1.8.x** закрыта с 1.8.1 (стабилизация перед талантами); **1.7.x** заморожена
  с 1.7.6; **1.6.x** — с 1.6.15.
- **Хотфиксы 1.9.0.N** — только критические баги (потеря данных, краш,
  эксплуат-уязвимость). Никаких новых механик по умолчанию.
- Дорожная карта: 1.9.1 — таланты в TTK-харнессе + баланс-патчи плейтеста;
  1.10.x — кастомная броня/сет-слой (Oraxen) как источник высоких avoid/резист
  чисел «со шмотом».
- Теги: `v<version>` на каждый релиз; артефакт прикрепляется к GitHub Release.

## Заметки разработчику

- Сборка: `mvn -B clean package`; артефакт `target/raskol-classes-<version>.jar`.
- CI: workflow «RaskolClasses Build» на каждый пуш; красный ран = блок релиза.
- Deprecation-политика: долг `Sound#getKey()` закрыт в 1.7.x (FxService читает
  `Registry.SOUNDS` через NamespacedKey); новых deprecated-вызовов не добавлять.
- Политика WARNING: однострочные сообщения без стектрейсов; стек только там,
  где без него не найти причину (коррупт хранилища в SafeStorage).
- UI-контракт талантов: управление деревом живёт только в Книге класса;
  команды талантов не добавлять без явного решения владельца.
